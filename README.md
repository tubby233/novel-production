# 小说生成器（PySide6 + DeepSeek）

一个面向 Windows 的桌面小说生成工具：粘贴大纲 → 自动切分章节 → 并发流式生成正文 → 独立检查对话 → 用户决策 → 一键导出 TXT。
最终使用 PyInstaller 打包为**免安装绿色文件夹版**（Win10 / Win11，目标机器无需 Python 环境）。

---

## 零、直接下载使用（推荐）

到 **[Releases](https://github.com/tubby233/novel-production/releases/latest)** 下载：

| 附件 | 说明 |
|---|---|
| `novel-production-v1.0.0-portable-win64.zip`（约 54 MB） | **绿色便携版**：解压到任意目录，双击 `NovelGen.exe` 即可运行，**不需要安装 Python 与任何依赖** |
| `novel-production-v1.0.0-source.zip`（约 0.2 MB） | 源代码压缩包（不含 `config.json` 等运行期数据） |

便携版使用步骤：

1. 把 zip 解压到任意目录（U 盘、桌面、D 盘都行），路径尽量不含特殊字符；
2. 双击 `NovelGen.exe`（首次运行会在同级目录自动生成 `config.json`、`chapters.json`）；
3. 菜单 **设置 → API 与模型** 填入 DeepSeek `api_key`，点「测试连接」确认可用；
4. 粘贴/导入大纲 → 点「切分章节」（会让你输入小说名完成"立项"）→ 工具栏 **全量生成**；
5. 出问题先看工具栏的 **运行日志** 按钮（独立窗口）。

> 整个文件夹可以整体拷到别的 Win10/Win11 电脑继续用；设置与小说数据都在里面。
> 放进 `C:\Program Files` 这类只读目录时，配置会自动回退到 `%APPDATA%\NovelGen`（不会报错）。

验证下载的包是否完整（不需要 Python 环境）：

```bat
set NOVELGEN_SELFCHECK=1
NovelGen.exe
:: 然后打开同目录的 selfcheck.txt，末尾应为“全部通过”
```

## 一、核心设计原则

1. **程序逻辑不依赖 AI 回复的具体格式。** 所有需要程序处理的内容，都由用户在设置界面通过"提示词 / 消息模板"明确指定；程序只做 **字符串替换**、**状态流转**、**界面展示**，不做任何基于自然语言理解的解析。
2. **所有发给 AI 的消息都由模板生成**，模板可在设置界面编辑并持久化。占位符替换是唯一入口（`core/message_templates.py`）。
3. **所有 assistant 输出都要求完整正文**，模板中明确禁止 diff / 局部修改 / 只输出片段。
4. **程序侧不判定"合格/不合格"**，也不做重生成次数上限；循环完全由用户手动控制。
5. **每个对话（生成 / 检查）拥有独立的深度思考参数**，互不影响。
6. **所有配置参数、选项、按钮都提供 ⓘ 悬浮解释**，说明集中维护在 `core/param_help.py`。

> 前提：每章大纲自带"本章内容 + 出场角色 + 前情提要 + 后续剧情"，各章相互独立，
> 因此程序可以放心地**全量并发**处理，不需要跨章上下文。

## 五、使用流程

### 1. 大纲输入与切分
* 在左侧"大纲文本"区域粘贴大纲，或点 **导入文件**（支持 `utf-8 / utf-8-sig / gbk / gb18030 / big5`）。
* 点 **切分章节**：按"章节标题正则"切分，匹配 `第一章 / 第1章 / 第 1 章 / 【第三章】 / Chapter 4` 等写法。
* **切分成功即触发立项**：程序请你输入**小说名**，并在"项目根目录"（默认 `我的文档\NovelGenProjects`，
  可在设置里修改）下新建一个以小说名命名的文件夹，把这部小说的数据全部放进去：

  ```
  我的文档\NovelGenProjects\星海归途\
     ├─ chapters.json       章节、正文、检查结果、状态、大纲快照
     ├─ conversations.json  全部生成/检查对话（含思维链，AI 每回复完一次就更新）
     ├─ outline.txt         大纲原文（纯文本，便于外部编辑与恢复）
     └─ project.json        项目信息（版本 / 小说名 / 创建与更新时间）
  ```

  同名文件夹已存在且非空时会提示换名，**不会静默覆盖**。取消立项不会影响本次切分，数据继续写在上次的位置。
* **切分新大纲不会污染原项目**（重要）：切分后到新项目建立之前的这段时间，
  自动保存被**完全挂起**（连已经排队的那一次写入也会被取消），
  因此磁盘上的原项目保持原样，新章节只会写进**新项目**的文件夹。
  想回头继续原小说，用 **项目 → 打开项目** 即可，进度与对话都在。
* 读取已有项目：菜单 **项目 → 打开项目**（列出项目根目录下的全部小说，也可"从文件夹打开…"直接选目录）；
  下次启动会**自动打开上次使用的小说**，并**恢复该小说全部对话历史**（见第八节"对话存档"）。
* 重新切分时的提示会区分情况：**已立项** → 明确告诉你"旧内容已存档、不会丢失"，
  可以直接切分新大纲来做另一部小说；**还没立项** → 才提醒"存在丢失风险，建议先导出或先立项"。
* 未匹配到任何章节时，程序给出两个兜底选项：**整篇作为一章** / **按空行分段**（不会静默产出空列表）。
* 列表项支持：勾选（批量生成）、右键 **编辑大纲 / 重命名 / 删除**、按状态过滤显示。
* 每章大纲整体作为**一个输入单元**，程序不再做更细粒度切分。

### 2. 生成与检查
* 工具栏 **全量生成 / 生成选中**，或章节视图的 **生成正文**。
* 提交后章节立刻进入 **排队中** 状态：任务一定排在**队列末尾**（FIFO），界面同时在提示条里说明
  "已提交、排在队尾、轮到就自动开始"；并发配额空出后状态自动变为**生成中**。
  想反悔就点 **停止本章**——排队中的任务会被撤下并回到提交前的状态。
* 并发数由设置（或工具栏）决定；每章对应一个**独立的生成对话**（保留 message history）。
* 正文生成完成后自动进入检查（可在设置中关闭）：检查使用一个**全新的独立对话**，system 为"检查提示词"，首条 user 消息为检查模板填充正文后的内容。
* **检查对话默认关闭深度思考**（省时省钱）；需要更深度的检查时，在检查视图点 **对话设置**，
  在**新窗口**里单独打开即可。
* 检查结果原样显示在可编辑文本框中，**等待用户决策**。

### 2.1 查看方式（默认极简，需要时才展开）
所有内容区都遵循"**先看结果、按需看过程**"：

| 位置 | 默认显示 | 展开方式 |
|---|---|---|
| 章节视图 · 正文（章节**不在**"检查中/待决策"时的默认页） | 最后一次生成的完整正文；**正在生成时这里是逐段实时追加的流式输出** | 点 **✎ 编辑正文** 可直接修改导出内容 |
| 章节视图 · 生成对话 | **只显示最后一次 assistant 输出的正文** | 点 **查看详细对话** → 完整 message history；再点 **只看最后正文** 收起 |
| 章节视图 · 检查视图（**"检查中/待决策"时的默认页**） | 上方检查结果可编辑框 + 决策行；下方**完整检查对话默认已展开** | 检查结果框高度**可直接拖动**它和对话之间的分隔条调整，也可点「放大结果框」按预设比例切换 |
| 决策行（通过 / 按要求重新生成正文 / 暂不处理） | **只在"待决策"时出现**，且只在正文视图与检查视图显示 | 无需展开；切到"生成对话"视图会自动隐藏 |
| 对话内的全部消息 | 逐条折叠 | 对话标题栏的 **折叠全部 / 展开全部** 一键处理（含 AI 回复与软件发给 AI 的消息） |
| 对话内的深度思考参数 | **不在主界面展开** | 点该对话标题栏的 **对话设置** → 在**独立窗口**中设置 |
| 思维链 | 默认折叠，超阈值（默认 2000 tokens）自动收起 | 点 **展开思考过程** |
| 原始消息历史 | 默认隐藏 | 点 **消息历史(JSON)** |
| 任务队列面板 | 默认隐藏 | 工具栏/菜单 **任务队列**（详见 2.3） |
| 运行日志 | **默认不显示，也不占主界面空间** | 工具栏 **运行日志** 或菜单 **帮助 → 运行日志** → 在**新窗口**中打开（有警告/错误时会自动弹出） |

顶部条固定三个与视图无关的操作，**任何视图下都能直接点**：**停止本章 / 触发检查 / 重新生成**；
右侧是**视图切换按钮组**（`正文` / `生成对话` / `检查视图`），**单击一次即切换**，当前视图为蓝底白字。

顶部条下面是**决策行**：**通过 / 按要求重新生成正文 / 暂不处理**。
它**只在章节处于"待决策"状态时出现**，并且**只在正文视图与检查视图**显示
（"生成对话"视图是查看/继续对话的地方，不显示决策按钮）。

工具栏右端还有两个按钮：**任务队列**（右侧队列面板，可拖动调整优先级）与 **运行日志**（独立窗口）。

切换章节时的默认视图**跟随状态**：**检查中 / 待决策 → 检查视图**（此时最需要看检查结果与决策按钮），
其余状态 → 正文页；其余展开状态自动回到默认（收起）。

### 2.2 检查 → 决策 → 重新生成的推荐操作顺序
1. 点顶部 **触发检查** → 自动切到 **检查视图**，并展示**完整检查对话**（可实时看到检查过程）。
2. 检查完成后，**检查对话的输出会自动填入上方"检查结果"文本框**，可直接手动修改（删掉不认可的意见）。
3. 点右侧 **↻ 按要求重新生成正文** → 任务排在队列末尾（状态"排队中"，界面给出提示），
   界面回到 **正文页**，新正文在那里逐段实时显示；生成完成后自动再次进入检查环节。
4. 满意时点 **✓ 通过**（决策行）；暂不决定就点 **暂不处理**。
   （不想参考检查结果时，用顶部条的 **重新生成** 附上自己的指令。）

* **正文字数由程序统计**：触发检查时程序算出该章字数（不计空格与换行），
  通过检查消息模板里的 `{word_count}` 占位符发给 AI，并要求它不要自己数，避免统计偏差。
* 模板占位符一览：`{outline}`（首次生成）、`{content}` / `{word_count}`（检查）、
  `{check_result}`（按要求重新生成）、`{user_input}`（重新生成）。

### 2.3 任务队列面板（看队列 + 拖动调优先级）
工具栏/菜单 **任务队列** 打开右侧面板：

* 上半部分「正在运行」（只读）：当前真正在跑的任务，数量由并发数决定。
* 下半部分「排队中」：**从上到下就是执行优先级**，最上面的最先执行。
* **直接拖动条目即可调整优先级**；也可以用 **置顶 / 上移 / 下移 / 移出队列** 按钮。
* 调度器只在**有空闲并发槽位时**才把任务从队列里取走，因此队列里显示的就是
  "还没轮到"的任务——拖动排序始终有效，不会出现"刚拖完却发现它已经被取走"。
* 调整顺序**不会打断正在运行的任务**。
* 面板每 0.7 秒自动刷新一次，也可以点「立即刷新」。

状态栏一直显示「队列 N ｜ 运行 M」，不看面板也能知道堵了多少。

### 3. 用户决策
| 按钮 | 位置 | 行为 |
|---|---|---|
| 触发检查 | 顶部条（任何视图可用） | 新建检查对话再查一次，并跳到检查视图看完整对话 |
| 重新生成 | 顶部条（任何视图可用） | **会自动选对做法**：待生成/出错（含刚清空生成对话）时 → 直接把本章大纲重新发给 AI；已有正文且对话还在时 → 弹框收集额外指令（可空）填入 `{user_input}` 后重写。任务入队后提示条给出反馈 |
| 重新生成（按大纲） | 顶部条（待生成/出错时显示的形态） | 同上第一种做法，不弹输入框 |
| 按要求重新生成正文 | **决策行（正文/检查视图，待决策时出现）** | 取**当前编辑框里的文本**填入 `{check_result}`，追加到生成对话并重新生成，随后回到正文页；任务入队后提示条给出反馈 |
| 通过 | **决策行（正文/检查视图，待决策时出现）** | 该章标记为"合格" |
| 暂不处理 | **决策行（正文/检查视图，待决策时出现）** | 保持状态不变 |
| 生成正文 | 正文页工具条 | 首次生成（仅"待生成/出错"可用） |

* 生成完成后会**再次自动进入检查**（若开启自动检查）。
* 没有任何自动判定、没有重生成上限。
* **清空生成对话不会丢大纲**：每次下发生成任务时都会把该章大纲单独存成快照
  （`chapters.json` 里的 `outline_snapshot`），清空对话后本章状态回到 **待生成**，
  此时点 **重新生成（按大纲）** 会重新把大纲发给 AI，而不是按修改建议重写。
* 清空对话会**同步清空界面上的对话视图**（不必切换页面刷新）。

### 4. 操作互斥规则
* 当章节处于"生成中 / 检查中"时，下列操作**禁用**：触发检查、重新生成、按要求重新生成正文、接受、暂不处理、对话内手动发送。
* 处于"排队中"时：**生成/触发检查/重新生成**同样置灰（避免重复排队），但 **停止本章** 仍可用（可把排队的任务撤下来）。
* 这些按钮采用"**视觉置灰但保持可点击**"的实现：点击时会明确提示 *"请等待当前生成/检查完成或先停止"*，并在同一界面提供 **停止本章** 入口（完全 `setEnabled(False)` 的按钮无法响应点击，也就给不出提示）。
* 忙状态下仍可用的操作：停止、查看/复制正文、查看思维链、查看消息历史、编辑正文文本框。
* 停止某一章后，该章**上一轮任务遗留的信号会被自动丢弃**（引擎为每次生成/检查分配递增的 run_seq），
  不会出现"新一轮正在流式输出、却被上一轮的结束信号清空"的情况。
* **用户主动停止不是报错**：点"停止本章/停止全部"或清空对话等手动操作触发的中断，
  只记一条 `info`（"已按你的要求停止…"）并保留已收到的内容，
  **不会写 warn/error 日志、也不会自动弹出日志窗口**；章节状态回到"待检查/待生成"，
  已经是"待决策/合格"的章节保持原状态，不会被冲掉。

### 5. 导出
* 工具栏 **一键导出 TXT** → 选择范围：
  * **导出全部**；
  * **仅导出已合格章节**（只导出你点过"通过"的章节）。
* **导出内容就是各章"生成正文"的顺序合并**：生成正文里本来就带章节标题，
  因此程序**既不添加章节标题、也不添加 `【第 N 章】章节名` 这类定位行**，一个字都不多写。
* 需要标记待办时，可勾选 **在未确认章节正文前单独加一行标记**（默认关闭）——
  它只在正文之前单独占一行，不改动正文；未确认章节仍可在文末附上"最后一次检查结果"。
* 正文取"最后一次 assistant 输出的 content"，**原样导出**（不解析、不修剪；思维链永不导出）。需要修剪时用 **✎ 编辑正文**。
* **默认文件名 = 当前小说项目名**（如 `星海归途.txt`）；未立项时用 `novel_export.txt`。
* **默认目录 = 设置里的「默认导出目录」**（"设置 → 界面与流程"里可改成任意文件夹），
  **不是**项目文件夹；在对话框里手动改过目录后，该目录会成为新的默认值。
* 编码默认 `utf-8-sig`（Windows 记事本打开不乱码）。

## 六、参数与默认值（依据 DeepSeek 官方文档）

官方文档来源：
[模型 & 价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing) ·
[思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode) ·
[Chat Completions API](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion) ·
[限速与隔离](https://api-docs.deepseek.com/zh-cn/quick_start/rate_limit)

| 参数 | 默认值 | 说明 |
|---|---|---|
| `model` | **`deepseek-flash`**（DeepSeek-V4.1-Flash） | 可手动输入其它 id；官方枚举为 `deepseek-flash` / `deepseek-v4-pro` |
| `base_url` | `https://api.deepseek.com` | 未填版本段时保存时自动补 `/v1` |
| `max_tokens` | **393216**（384K，模型上限） | 手输 + 预设（8K / 64K / 128K / 384K）；是**上限不是目标** |
| 上下文窗口 | 1,048,576 tokens（1M） | 只读展示；程序在发送前用估算做预算保护 |
| `temperature` | 1.0 | **思考模式下不生效**（参数本身有效，仅思考模式忽略） |
| `top_p` | 1.0 | 思考模式生效但**下限 0.95**（自动抬升）；非思考模式**恒为 1.0** |
| `frequency_penalty` / `presence_penalty` | — | **已被 DeepSeek 官方标记为 deprecated**（"传入该参数将不会产生任何效果"），因此**本程序已移除这两项**：设置界面不再提供、请求不发送、旧配置中的值会被忽略并提示 |
| `concurrency` | 8 | 账号级上限：`deepseek-flash` 2500 / `deepseek-v4-pro` 500；超限返回 429 |
| `timeout` | 1800 秒 | 服务端保活：10 分钟未开始推理才断连，故客户端超时需足够大 |
| `user_id` | 空 | 可选，放入 `extra_body`，用于 KVCache / 调度隔离 |
| 思考开关 | 生成：启用；**检查：关闭（默认）** | `extra_body={"thinking": {"type": "enabled"/"disabled"}}`；检查对话的深度思考可在检查视图的"对话设置"（新窗口）里单独打开 |
| `reasoning_effort` | 生成：`high`；检查：`max` | `low / high / max`（官方另接受 `none` 表示关闭思考）；映射：`medium/xhigh→high`、`ultra→max` |

程序自动遵守的约束（设置界面会置灰/标注，并在"本次生效参数预览"里回显真实入参）：

* 思考模式下 `temperature` 不生效（设置不报错，API 忽略）。
* `top_p` 在思考模式下下限 0.95；非思考模式下恒为 1.0。
* `frequency_penalty` / `presence_penalty` 已弃用，程序完全不发送；需要抑制复读或推动情节时，改用提示词或"重新生成"的指令。
* 请求**不携带 `tools`**，因此 `reasoning_content` **无需回传**（程序只在本地保留用于展示，历史消息只发 `role + content`）。
* 思维链 token 计入 `completion_tokens`，同样计费；高峰时段为北京时间周一至周五 9:00–12:00、14:00–18:00，其余为空闲时段。

## 七、打包为绿色便携文件夹（免安装、免 Python）

**推荐做法（一条命令）**：

```bat
cd novel_gen
pip install -r requirements.txt pyinstaller
python make_portable.py
```

产物是 **`dist\NovelGen\` 一个文件夹**，自带 Python 解释器、Qt（PySide6）、openai/httpx、CA 证书与全部资源：

```
dist\NovelGen\
  NovelGen.exe          ← 双击运行（无控制台窗口）
  _internal\            ← 运行库：python3.dll、PySide6(含 qwindows.dll 平台插件)、
                           openai/httpx、certifi\cacert.pem、assets\(style.qss、icon.ico)
  使用说明.txt          ← 面向最终用户的说明（可直接交给别人）
  config.json           ← 首次运行自动生成（含 api_key，注意保管）
  chapters.json         ← 章节与对话数据（自动保存）
```

把整个 `NovelGen` 文件夹拷到任何 **Windows 10 / 11（64 位）**电脑上双击即可运行，
目标机器**不需要安装 Python、不需要联网安装依赖、不需要管理员权限**。
移动时请保持 `NovelGen.exe` 与 `_internal\` 在一起。

### 验证打包结果（不需要 Python 环境）

```bat
python tools\verify_portable.py                 :: 检查 dist\NovelGen
:: 或直接在目标机器上：
set NOVELGEN_SELFCHECK=1
NovelGen.exe
type selfcheck.txt        :: 末尾出现“全部通过”即表示文件夹完整可用
```

`NOVELGEN_SELFCHECK=1` 是 exe 内建的自检开关（见 `main.py`）：**不显示界面**，
依次检查依赖导入、Qt 平台插件、资源文件、配置读写、消息模板占位符、参数说明表、
章节切分与主窗口构造，把结果写入数据目录下的 `selfcheck.txt`，全部通过时退出码为 0。
（实测：绿色文件夹里 exe 自检 1.8 秒、8 项全 OK。）

### 两种打包形态对比

| 形态 | 配置 | 产物 | 说明 |
|---|---|---|---|
| **绿色文件夹（推荐）** | `build.spec` | `dist\NovelGen\` 文件夹 | 启动快、结构清晰、便于整体拷贝；`python make_portable.py` 一键完成 |
| 单文件 | `build_onefile.spec` | `dist\NovelGen.exe` | 便于单文件传输，但每次启动都要把 Qt 解包到 %TEMP%，首次启动慢、更易被杀软误报 |

### spec 已处理好的坑

* `openai / httpx / httpcore / anyio / pydantic / sniffio / h11 / idna` 的**隐式导入**用 `collect_submodules` 兜底；
* `certifi` 的 CA 证书用 `collect_data_files` 一并打包（否则 HTTPS 校验失败）；
* `assets/`（样式表、图标）作为数据打包，运行时通过 `core/paths.resource_path()` 定位；
* 排除 `tkinter / numpy / matplotlib / PIL / PyQt5 / PyQt6 / PySide2 / pytest` 等无关包；
* `upx=False`（UPX 常被杀软误报，且可能损坏 Qt 插件）；
* `console=False`（windowed），未捕获异常会弹窗并把堆栈写入数据目录下的 `crash.log`。

### 数据目录（保证"搬到哪都能带着设置走"）

选择顺序（实现见 `core/paths.py`）：

1. 环境变量 `NOVELGEN_DATA_DIR`（把程序放在只读位置时的兜底）；
2. **exe 同目录** —— 绿色版首选：`config.json` / `chapters.json` 跟着文件夹走；
3. `%APPDATA%\NovelGen\` —— 上述目录不可写（例如放进 `C:\Program Files`）时自动回退。

设置界面底部与状态栏都会显示**实际生效的路径**。程序不会写注册表、不写系统目录，删除文件夹即完成卸载。

## 八、数据与持久化

> **本仓库不包含任何运行期数据。** `config.json`（内含**明文 `api_key`**）、`chapters.json`、
> `conversations.json`、`*.log`、`build/`、`dist/` 都已在 `.gitignore` 中排除 ——
> 克隆下来第一次运行时会自动生成全新的默认配置，**不要把自己的 `config.json` 提交上去**。

| 文件 | 内容 |
|---|---|
| `config.json` | 全部设置：API、采样、思考默认值、提示词、消息模板、界面与导出选项、默认导出目录、项目根目录、上次打开的项目（**明文，含 api_key，注意保管**） |
| `<项目根目录>/<小说名>/chapters.json` | 该小说的章节数据自动保存：大纲、**大纲快照**、状态、正文、检查结果、历次检查 |
| `<项目根目录>/<小说名>/conversations.json` | **对话存档**：该小说全部章节的生成/检查对话（含思维链、每条消息的来源与 token 用量）。读取项目时优先用它恢复，保证"接着之前的对话继续聊、正文不被清空" |
| `<项目根目录>/<小说名>/outline.txt` | 该小说的大纲原文（纯文本，便于外部编辑与恢复） |
| `<项目根目录>/<小说名>/project.json` | 项目信息：版本、小说名、创建与更新时间 |
| `chapters.json`（数据目录下） | 旧版/未立项时的章节数据（兼容保留） |
| `crash.log` | 未捕获异常堆栈（仅出错时生成） |

**对话存档的更新时机**（每次都是原子写入，覆盖旧的 conversations.json）：

1. **AI 每回复完成一次**（生成/检查/对话内手动消息结束后）自动更新；
2. **关闭项目或切换到其它项目**时更新；
3. **关闭软件**时更新。
   另外清空对话也会立刻落盘，避免"清空了却又读回旧对话"。

各阶段的数据都会自动保存，**关掉程序再打开就能接着写**：

* **立项后**，章节数据在生成/检查/编辑时**自动保存**（防抖 1.5 秒）到该小说的项目文件夹；
  **未立项**时仍写回全局数据目录，保证随时可切换。
* **切分新大纲、正在等你输入小说名的这段时间里，自动保存是挂起的**：
  避免"新大纲的章节"被写进上一个项目而覆盖原进度（这是修过的一个真实缺陷，
  `tools/smoke_test.py` 里有对应的回归用例）。
* 启动时按"**上次打开的项目 → 全局数据目录**"的顺序恢复；退出时保存窗口几何、大纲文本与当前项目路径。
* 读取项目时的顺序是 `chapters.json`（章节/正文/状态）→ `conversations.json`（对话），
  **对话存档会覆盖 chapters.json 里内嵌的对话**，因此重新打开后可以接着之前的对话继续。
* 整个项目文件夹可以直接拷贝/压缩，就是这部小说的完整备份（含全部对话历史与思维链）。
* 章节状态持久化时，退出瞬间处于"生成中/检查中/排队中"的章节会回落到可继续操作的状态
  （有正文 → 待检查，无正文 → 待生成），不会出现重启后卡在"排队中"。

## 九、常见问题

**1. 提示"缺少依赖：请先执行 pip install -r requirements.txt"**
运行环境缺少 `httpx`/`openai`，按提示安装即可；打包版一般不会出现。

**2. `401 / 403`（API 密钥无效或没有访问权限）**
检查 `api_key` 是否填对、是否已过期；中转服务要确认 `base_url` 与 key 属于同一服务商。

**3. `400 model not found`**
模型名写错。官方 id 是 `deepseek-flash`（DeepSeek-V4.1-Flash）或 `deepseek-v4-pro`。

**4. `429`（限速/并发超限）**
并发数以**账号**为单位计算。请在工具栏或设置里降低并发数（程序会在运行日志里给出提示，
日志窗口用 **帮助 → 运行日志** 打开）。

**5. 正文被截断**
日志/检查区会提示 `finish_reason=length`。调大 `max_tokens`；注意开启思考时思维链也占用该额度。

**6. 请求超时**
思考强度 `max` + 大章节耗时较长。可调大"请求超时"，或降低 `max_tokens` / 思考强度。

**7. 改了 temperature 没效果**
若思考模式开启，`temperature` 本就不生效（文档规定）。看"本次生效参数预览"里 API 实际收到的参数。

**8. 导出中文乱码**
使用默认 `utf-8-sig`；若目标软件只认 GBK，在导出对话框里切换编码。

**9. 导出文件里为什么没有"【第 N 章】"这类行**
按需求去掉了：生成的正文里本来就带章节标题，程序不再补任何题目或定位行，
导出内容就是各章正文的顺序合并。想要在成品里定位未确认章节，勾选
**在未确认章节正文前单独加一行标记**即可（默认关闭）。

**10. 检查结果框太小 / 太大**
它在检查视图里可以**自由调整高度**：把鼠标移到"检查结果"框与下方"检查对话"之间的
分隔线上拖动即可。也可以点右上角的 **放大结果框** 按钮在几种预设比例间切换。
高度会被保留到下次切换视图。

**11. 字数是谁统计的**
**程序**统计。触发检查时，程序先算出该章正文字数（不计空格与换行），
通过 `{word_count}` 占位符填进检查消息，并在模板里明确告诉模型"不要自己数字数"。
因此检查结果里的字数不会出现偏差；你也可以在自己的检查模板里直接引用 `{word_count}`。

**12. 点了"重新生成"但好像没反应**
正文页/检查视图顶部会出现蓝色提示条，说明任务**已排在队列末尾**（章节状态显示为"排队中"）。
任务多时请等并发配额空出，或在状态栏看队列长度；也可以点"停止本章"撤下排队中的任务。

**13. 点了"清空对话"后还能重新生成吗**
可以。清空**生成对话**后本章状态回到"待生成"，右上/顶部的按钮会变成 **重新生成（按大纲）**：
点它就是把本章大纲重新发给 AI 生成一遍（不是按修改建议重写）。
大纲在下发任务时会单独存成快照（`chapters.json` 的 `outline_snapshot`），与对话完全独立，因此清空对话不会影响它。

**14. 停止任务为什么还弹日志？**
"停止本章 / 停止全部"以及清空对话这类**手动操作**触发的中断都**不算报错**：
只记一条 `info`（"已按你的要求停止…"）、保留已收到的内容，章节回到"待检查/待生成"，
**不会写 warn/error、也不会自动弹出日志窗口**。日志窗口只在点工具栏/菜单的 **运行日志**、
或真的出现警告/错误时才出现。

**15. 重新打开项目后还能接着之前的对话吗？**
可以。对话会持久化到项目文件夹里的 `conversations.json`（AI 每回复完一次就更新；
关闭项目、切换项目、关闭软件时也会更新）。读取项目时它优先于 chapters.json 内嵌的对话，
因此正文不会被清空，生成/检查对话也能接着继续。

**16. 某一章一直显示"排队中"怎么办**
先打开工具栏的 **任务队列** 面板看它到底在不在队列里：

* 在队列里 → 就是单纯还没轮到（并发数用完了）。可以把它 **拖到队首**，或调大并发数，
  或点 **移出队列** 取消它。
* 不在队列里、也没有在运行 → 这是异常遗留状态，程序会自动检测并把它恢复到
  "待生成/待检查"（日志里会写一条"排队中但没有对应任务，已自动恢复…"）。
  也可以直接对那一章点 **停止本章** 立刻恢复。

**17. 手动删掉了 config.json 会怎样**
等于"恢复出厂设置"：程序启动时会**自动在数据目录里重新生成一份完整的默认 config.json**，
并在弹出的"配置提示"里告诉你这件事。如果原文件是被写坏的（非法 JSON），
旧文件会先备份成 `config.json.bak` 再重新生成。已有的设置不会被默认值覆盖——只有文件缺失/损坏时才会重建。

**18. 打包后双击没反应**
查看 exe 同目录（或 `%APPDATA%\NovelGen\`）下的 `crash.log`；常见原因是杀毒软件拦截了 onefile 解压，
可把 exe 加入白名单，或改用 `--onedir`（把 `build.spec` 中的 `EXE(...)` 换成 `COLLECT(...)` 结构）。

## 十、开发约定（改动时请遵守）

1. 新增参数 → 必须在 `core/param_help.py` 注册说明，并在界面用 `HelpIcon("<key>")` 或 `attach_help(...)` 挂上。
   `MainWindow._qa_check()` 会在启动时报告缺失项。
   （注意：`QAction` 没有 `setToolTipDuration`，工具栏动作请直接 `setToolTip(...)`。）
2. 新增发给 AI 的消息 → 必须走 `core/message_templates.py` 的 `render_template()`，禁止在别处拼接并直接发送。
3. 不要用 `str.format` 处理模板（正文里的 `{}` 会炸）；只用 `str.replace`。
4. 状态只能经 `Engine.transition()` 修改；界面不得自行改状态，只响应 `chapter_state_changed`。
   "排队中"也走同一套迁移表：`submit_*` 在 UI 线程置为 `QUEUED`，任务真正开始时迁到
   `GENERATING`/`CHECKING`，被停止时用 `Chapter.pre_queue_state` 回退。
5. 任何网络 / 耗时操作都必须放在引擎线程的协程里，UI 线程不得阻塞。
6. `reasoning_content` 只用于展示，永不写进请求、永不导出。
7. 小说数据一律通过 `core/project.py` 的读写接口落在项目文件夹里，不要另起一套路径拼接。
8. 自检脚本（`tools/smoke_test.py` / `tools/e2e_test.py`）不要用 `tempfile.mkdtemp` 建工作目录：
   它用 0o700 建目录，在受限环境下会让随后在其中的 `mkdir` 报 WinError 5；请用脚本里的
   `temp_dir()` 辅助函数。
